كيف تربط تطبيق أندرويد أو سطح المكتب بأجهزة العتاد والـ Arduino وقارئات الباركود؟ الدليل الهندسي لبروتوكول Serial وUSB-OTG

تاريخ النشر: 08 نوفمبر 2026 - التصنيف: برمجة وتطوير - تطوير الهواتف والأنظمة المتعددة

في أنظمة نقاط البيع (POS)، والمختبرات الصناعية، وأنظمة الطاقة الشمسية الذكية، وأجهزة الفحص الميداني، لا يعمل التطبيق بمعزل عن العالم المادي؛ بل يُطلب منه الاتصال المباشر عبر كابل USB-OTG أو منفذ COM / TTY لقراءة ميزان إلكتروني، أو استقبال رموز من قارئ باركود صناعي، أو طباعة فاتورة حرارية بأوامر ESC/POS، أو التخاطب مع لوحة متحكم دقيق (Arduino / ESP32 / STM32) ومودم اتصالات!

كيف يعمل بروتوكول الاتصال التسلسلي (UART / USB-Serial) تحت الغطاء؟ ولماذا تنهار كثير من التطبيقات عند اهتزاز كابل الـ USB أو تقطّع البيانات الثنائية (Byte Streams)؟ في هذا الدليل الهندسي من مدونة كونكت تاق، نشرح معمارية التخاطب مع العتاد عبر منصتي أندرويد وسطح المكتب (Desktop JVM)، ونستعرض كيف بنينا حزمة serial-lib-kmp مفتوحة المصدر في قسم المكاتب البرمجية، وتطبيقاتنا العملية في تطبيق سطور للباركود وتطبيق خبير لفحص العتاد ومنظومة ذَود (DHAWD ADB).

خلاصة تنفيذية لمهندسي الأنظمة المدمجة ومطوري التطبيقات
  • جسور التحويل التسلسلي (USB-to-UART Bridges): تتواصل الهواتف والحواسيب مع العتاد عبر شرائح جسر قياسية أشهرها FTDI (FT232R)، وSilicon Labs (CP210x)، وWCH (CH340/CH341)، وProlific (PL2303)، ومعيار CDC/ACM.
  • التطابق الصارم لمعاملات الإطار (8N1 & Baud Rate): يجب أن تتطابق سرعة البود (مثل 9600 أو 115200) وعدد بتات البيانات والتكافؤ والتوقف بين الكود والعتاد لتجنب تلف البيانات.
  • تجميع الإطارات (Frame Delimiting): لا تفترض أبداً أن استدعاء قراءة واحد يعيد رسالة كاملة؛ استخدم دائماً مجمع بايتات (Packet Framing) يعتمد على محارف الفصل (\n) أو ترويسة الطول واختبار CRC.
  • المراقبة وإعادة الاتصال التلقائي (Watchdog & Auto-Reconnect): توفر مكتبة serial-lib-kmp تدفقات Kotlin Flow تفاعلية مع مؤقت حراسة يعيد فتح القناة تلقائياً عند انقطاع الطاقة اللحظي.

1. كيف يعمل وضع المضيف (USB Host / OTG) وشرائح الجسر التسلسلي؟

في الحالة العادية، يعمل الهاتف الذكي عند توصيله بالكمبيوتر في وضع «الملحق / التابع» (USB Peripheral / Gadget Mode). لكن عند توصيل وصلة USB On-The-Go (OTG)، يكتشف منفذ USB Type-C مقاومة سحب أرضية على دبوس التحديد (CC / ID Pin)، فيتحول الهاتف فوراً إلى «مضيف رئيسي» (USB Host) يزوّد الجهاز المتصل بطاقة كهربائية (5V VBUS) ويدير تخاطب الحزم الرقمية معه!

بما أن المتحكمات الدقيقة (مثل Arduino وESP32) والموازين الرقمية تتحدث داخلياً بلغة TTL UART (إشارات منطقية متسلسلة على خطي إرسال TX واستقبال RX)، فإنها تستخدم شريحة إلكترونية وسيطة تُسمى جسر USB إلى Serial (USB-to-UART Bridge). في نظام أندرويد، يخاطب التطبيق هذه الشريحة في فضاء المستخدم (بدون صلاحيات روت) عبر واجهة UsbManager ونقاط النهاية الثنائية (Bulk Endpoints IN & OUT).

2. جدول معرّفات المصنّعين والشرائح القياسية (VID / PID) في العتاد

يُعرِّف كل جهاز USB نفسه للنظام عبر رقمين ست عشريين (Hexadecimal): معرّف المصنّع (Vendor ID — VID) ومعرّف المنتج (Product ID — PID). يوضح الجدول المرجعي التالي أشهر الشرائح التي ستصادفها عند ربط تطبيقاتك بالعتاد الخارجي:

الشريحة / البروتوكول معرّف المصنّع (VID) أشهر معرّفات المنتج (PID) الاستخدام الشائع في السوق
WCH CH340 / CH341 0x1A86 (6790) 0x7523, 0x5523 لوحات Arduino الاقتصادية، ESP8266/ESP32، وكابلات برمجة الراوترات
Silicon Labs CP210x 0x10C4 (4292) 0xEA60, 0xEA70 عقد ESP32 الاحترافية، أجهزة القياس الطبية، ومحولات Modbus الصناعية
FTDI FT232R / FT231X 0x0403 (1027) 0x6001, 0x6015 المعدات الصناعية الحساسة، أنظمة الطيران (Telemetry)، وكابلات الشبكات
USB CDC / ACM القياسي متعدد (مثل 0x2341) متعدد حسب الفئة Class 0x02 قارئات الباركود (في وضع Virtual COM)، لوحات STM32، والمودمات الخلوية

3. تشريح إطار البيانات التسلسلي: Baud Rate و8N1 والتحكم بالتدفق (Flow Control)

لأن بروتوكول UART غير متزامن (Asynchronous — أي لا يوجد سلك ساعة Clock Wire مشترك بين المرسل والمستقبل)، يجب أن يتفق الطرفان مسبقاً على أربعة معاملات دقيقة:

  • سرعة النقل (Baud Rate): عدد النبضات في الثانية؛ أشهرها 9600 (للموازين وقارئات الباركود البسيطة) و115200 (للوحات ESP32 والمودمات ونقل السجلات السريع).
  • بتات البيانات (Data Bits): قياسياً 8 bits (بايت واحد لكل محرف).
  • بت التكافؤ (Parity Bit): يُستخدم لاكتشاف انقلاب بت واحد بسبب التشويش الكهرومغناطيسي؛ ويكون إما بدون تكافؤ (None — N) أو زوجياً (Even — E) أو فردياً (Odd — O).
  • بتات التوقف (Stop Bits): فترة سكون في نهاية كل بايت لمزامنة المستقبل (عادةً 1 Stop Bit). ومن هنا جاءت التسمية الهندسية الشهيرة: 115200 8N1.

4. معضلة تجزئة البايتات (Packet Fragmentation): كيف تبني مجمّع إطارات لا يخطئ؟

الخطأ البرمجي الأكثر تسبباً في فشل تطبيقات العتاد هو كتابة كود يفترض أنه إذا أرسلت لوحة الـ Arduino السطر {"temp":26.4}\n، فإن حدث القراءة في الهاتف سيستلمه دائماً كقطعة واحدة! في الواقع الفيزيائي لناقل USB Bulk Transfer، قد يصل الجزء {"temp": في القراءة الأولى، ثم يصل الجزء 26.4}\n بعد 2 ملي ثانية في القراءة الثانية!

لذلك، يجب دائماً تمرير البايتات الخام الواردة عبر مجمّع إطارات تفاعلي (Reactive Line/Frame Assembler) قبل محاولة قراءتها أو تحويلها إلى نص أو JSON:

كود تجميع الحزم التسلسلية المقطّعة وإعادة الاتصال التلقائي بـ Kotlin Flow 
// دالة تحويل تدفق البايتات الخام المتقطعة إلى رسائل سطرية مكتملة (Line-Delimited Frames)
fun Flow<ByteArray>.assembleSerialLines(maxBufferSize: Int = 8192): Flow<String> = flow {
    val buffer = StringBuilder()
    collect { chunk ->
        buffer.append(chunk.decodeToString())
        // حماية الذاكرة في حال عدم وصول محرف سطر جديد بسبب ضوضاء الخط
        if (buffer.length > maxBufferSize) {
            buffer.clear()
        }
        var newlineIndex = buffer.indexOf('\n')
        while (newlineIndex != -1) {
            val completeLine = buffer.substring(0, newlineIndex).trimEnd('\r')
            buffer.delete(0, newlineIndex + 1)
            if (completeLine.isNotEmpty()) {
                emit(completeLine)
            }
            newlineIndex = buffer.indexOf('\n')
        }
    }
}

5. التطبيق البرمجي العابر للمنصات عبر مكتبة serial-lib-kmp وآلية Watchdog

لتوحيد كود التخاطب مع المنافذ التسلسلية بين نظامي أندرويد (USB-OTG) وسطح المكتب (Windows COM Ports / Linux ttyUSB)، طورنا في شركة كونكت تاق حزمة serial-lib-kmp المتاحة في قسم المكاتب البرمجية، والتي توفر المزايا الهندسية التالية:

  • واجهة برمجية موحدة (Unified SerialTransport Contract): تكتب منطق البروتوكول مرة واحدة في وحدة commonMain، وتتكفل المكتبة بتشغيله عبر UsbManager في أندرويد وعبر منافذ النظام الأصيلة في Desktop JVM.
  • مراقب الحراسة الذكي (Connection Watchdog & Auto-Recovery): في البيئات الصناعية ونقاط البيع، قد يتعرض كابل الـ USB لاهتزاز لحظي أو نبضة كهربائية تفصل الاتصال لجزء من الثانية. يقوم الـ Watchdog بمراقبة نبضات الجهاز (Heartbeat) وإعادة تهيئة المنفذ تلقائياً دون تجميد واجهة المستخدم.
  • دعم وضع التحديث البرمجي (DFU / Bootloader Mode): التحكم الدقيق بإشارات التحكم DTR (Data Terminal Ready) وRTS (Request To Send) اللازمة لإدخال لوحات ESP32 وArduino في وضع البرمجة وتحديث الفيرموير.

6. تطبيقات عملية في منظومة كونكت تاق: من نقاط البيع إلى الفحص العتادي وحماية المنافذ

تُستخدم تقنيات التخاطب العتادي والـ USB-OTG في عدد من أبرز منتجات وحلول كونكت تاق التي يمكنك استكشافها وتجربتها:

  • قراءة وتوليد الباركود لنقاط البيع والمخازن: يتيح تطبيق سطور (Satoor) لقراءة وتوليد الباركود التكامل السلس مع عمليات المسح السريع وإدارة الأصناف، ويتكامل في بيئات الشركات مع أنظمة إدارة الأجهزة المؤسسية ووضع الكشك (Kiosk Mode).
  • الفحص الهندسي لمنافذ ومستشعرات الجهاز: يمكّنك تطبيق خبير (Kabeer) لفحص العتاد والمستشعرات من التحقق من دعم هاتفك لميزة USB Host / OTG وفحص سلامة المستشعرات والبطارية والشاشة.
  • إدارة وصيانة أجهزة أندرويد عبر سطح المكتب: تعتمد منظومة ذَود (DHAWD ADB) لإدارة أجهزة أندرويد على قنوات الاتصال المباشر عبر USB والشبكة لتنفيذ أوامر الفحص والنسخ الاحتياطي وإدارة الحزم.
  • الأمن السيبراني وحوكمة منافذ الـ USB: للحماية من هجمات BadUSB / Rubber Ducky التي تنتحل صفة لوحة مفاتيح عبر منفذ OTG، توفر منظومتنا تطبيق سور USB (Soor USB) لحماية وحوكمة منافذ الـ USB.

7. الأسئلة الشائعة حول برمجة USB-OTG والاتصال التسلسلي

لماذا لا يتعرف هاتف أندرويد على لوحة Arduino أو جهاز Serial تلقائياً بدون مكتبة تعريف؟

لا تتضمن نواة أندرويد في معظم الهواتف التجارية تعريفات نواة مفعّلة لجميع شرائح الجسر التسلسلي (مثل CH340 أو FTDI أو CP2102). لذلك يتعامل التطبيق مع الجهاز في فضاء المستخدم (User-Space) عبر واجهة Android UsbHost API (UsbManager وUsbDeviceConnection)، حيث تقوم مكتبة الاتصال التسلسلي بترجمة أوامر البود ريت (Baud Rate) ونقل الحزم عبر نقاط النهاية (Bulk Endpoints IN/OUT) برمجياً دون الحاجة لصلاحيات الروت.

ماذا تعني إعدادات الاتصال التسلسلي 9600 8N1 أو 115200 8N1؟

يرمز الرقم الأول (9600 أو 115200) إلى سرعة نقل الإشارات في الثانية (Baud Rate)، ويجب أن تتطابق تماماً بين التطبيق والعتاد وإلا ستظهر رموز مشوهة. أما 8N1 فتعني: 8 بتات بيانات لكل حرف (8 Data Bits)، وبدون بت تكافؤ لفحص الأخطاء (N = No Parity)، وبت توقف واحد في نهاية كل إطار (1 Stop Bit).

كيف أعالج مشكلة تقطّع الرسالة الواحدة إلى عدة دفعات أثناء القراءة من منفذ USB-Serial؟

بروتوكول الاتصال التسلسلي ينقل تياراً مستمراً من البايتات (Byte Stream) ولا يعرف مفهوم «بداية ونهاية الرسالة» من تلقاء نفسه؛ فقد تصل جملة JSON أو رقم باركود مقسماً على قراءتين. الحل الهندسي هو استخدام مخزن تجميع مؤقت (Ring Buffer / Frame Assembler) ينتظر محرف الفصل المعتمد (مثل سطر جديد \n أو \r\n) أو يتحقق من طول الإطار ورمز التدقيق (CRC Checksum) قبل إصدار الرسالة الكاملة.

كيف أجعل تطبيقي يتصل بالجهاز التسلسلي تلقائياً عند توصيل كابل USB-OTG دون إزعاج المستخدم بطلب الإذن في كل مرة؟

يتم ذلك عبر تعريف فلتر أجهزة USB (device_filter.xml) يتضمن معرّف المصنّع (Vendor ID — VID) ومعرّف المنتج (Product ID — PID) للجهاز، وربطه بنية UsbManager.ACTION_USB_DEVICE_ATTACHED في ملف البيان. بمجرد موافقة المستخدم مرة واحدة مع تفعيل خيار «الاستخدام افتراضياً لهذا الجهاز»، يمنح النظام الإذن تلقائياً في كل مرة يُوصل فيها الكابل.
