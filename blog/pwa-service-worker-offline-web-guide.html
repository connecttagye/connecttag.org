كيف تحوّل موقعك الإلكتروني إلى تطبيق يعمل بدون إنترنت؟ الدليل الهندسي لتطبيقات الويب التقدمية (PWA) وإدارة الكاش عبر Service Workers

تاريخ النشر: 08 نوفمبر 2026 - التصنيف: برمجة وتطوير - تطوير الهواتف والأنظمة المتعددة

هل لاحظت أنه عند تصفحك لموقع كونكت تاق واستخدامك لأدواتنا التقنية ثم انقطاع اتصال الإنترنت فجأة، يظل الموقع قادراً على فتح الصفحات التي زرتها وتشغيل الأدوات البرمجية محلياً مع عرض شاشة تنبيه أنيقة للوضع غير المتصل (Offline Fallback) بدلاً من شاشة خطأ المتصفح الرمادية المزعجة؟ السّر الهندسي وراء هذه التجربة يكمن في معمارية تطبيقات الويب التقدمية (Progressive Web Apps — PWA) ومحرك Service Worker!

في هذا الدليل الهندسي التطبيقي من مدونة كونكت تاق، نشرح خطوة بخطوة كيف تحوّل أي موقع إلكتروني إلى تطبيق قابل للتثبيت على شاشة الهاتف وسطح المكتب، وكيف تختار استراتيجية التخزين المؤقت (Caching Strategy) المناسبة لكل نوع من الملفات، وكيف تمنع أشهر فخ يقع فيه المطورون وهو «بقاء الزوار عالقين على النسخة القديمة من الموقع بعد التحديث»، مع ربط عملي بـ أداة فحص الموقع والـ SEO وخدمة تطوير المواقع والأنظمة السحابية.

خلاصة تنفيذية لمطوري الويب ومهندسي الأداء
  • الأركان الثلاثة لأي تطبيق PWA: اتصال آمن مشفر عبر HTTPS + ملف بيان التطبيق (manifest.json) لتعريف الأيقونات ونمط العرض المستقل (standalone) + عامل خدمة مسجّل (Service Worker — sw.js).
  • لا توجد استراتيجية كاش واحدة تناسب كل شيء: استخدم Cache-First للخطوط والأيقونات الثابتة، وStale-While-Revalidate لملفات التصميم والصور، وNetwork-First لصفحات HTML وواجهات البيانات الحية.
  • إدارة الإصدارات وتطهير الكاش (Cache Versioning & Busting): اربط اسم مخزن الكاش في sw.js بمعرّف إصدار واضح (مثل v108) وامسح المخازن القديمة تلقائياً داخل حدث activate.
  • التشغيل المحلي داخل تطبيقات الهواتف: إذا كنت ترغب في تشغيل تطبيق ويب كامل داخل تطبيق أندرويد بدون إنترنت، يمكنك دمج مكتبتنا مفتوحة المصدر local-web-server من قسم المكاتب البرمجية في كونكت تاق.

1. ما هو تطبيق الويب التقدمي (PWA) وكيف يعمل الـ Service Worker كوكيل شبكي؟

تطبيق الويب التقدمي (Progressive Web App) هو موقع ويب مبني بمعايير الويب القياسية (HTML5, CSS3, JavaScript)، لكنه يمتلك قدرات تحاكي التطبيقات الأصيلة (Native Apps): يمكن تثبيته بأيقونة مستقلة على الشاشة الرئيسية للهاتف أو سطح المكتب، يعمل في نافذة كاملة بدون شريط عنوان المتصفح، ويستمر في العمل حتى عند انقطاع الإنترنت.

العقل المدبر وراء هذه القدرات هو عامل الخدمة (Service Worker)؛ وهو ملف جافاسكربت يعمل في خيط معالجة خلفي مستقل (Background Worker Thread) منفصل تماماً عن صفحة الويب الرئيسية (DOM). يمرّ الـ Service Worker بثلاث مراحل أساسية في دورة حياته (Lifecycle):

  1. التسجيل والتثبيت (Registration & Install): يقوم المتصفح بتنزيل ملف sw.js وتنفيذ حدث install، حيث يتم تخزين الملفات الحرجة للواجهة (App Shell: صفحة البداية، الخطوط، ملفات CSS/JS الأساسية، وصفحة offline.html) داخل واجهة Cache Storage API.
  2. التفعيل وتنظيف الإصدارات القديمة (Activate): بمجرد تفعيل النسخة الجديدة، يقوم الحدث activate بحذف أي مخازن كاش تابعة لإصدارات سابقة لتحرير مساحة تخزين جهاز المستخدم.
  3. اعتراض الطلبات الشبكية (Fetch Interception): يتحول الـ Service Worker إلى وكيل شبكي ذكي (Programmable Network Proxy) يعترض كل حدث fetch يطلبه الموقع ليقرر برمجياً: هل يجلبه من الكاش المحلي في جزء من الألف من الثانية أم من خادم الإنترنت؟

3. مقارنة استراتيجيات الكاش الثلاث: Cache-First مقابل Network-First مقابل Stale-While-Revalidate

الخطأ الأكبر الذي يرتكبه المبتدئون عند كتابة Service Worker هو تطبيق استراتيجية Cache-First على جميع ملفات الموقع بما فيها صفحات HTML! يؤدي ذلك إلى تجمد محتوى الموقع لدى الزائر وعدم رؤيته لأي مقالات أو تحديثات جديدة. الهندسة الصحيحة تقسم موارد الموقع حسب طبيعتها إلى 3 استراتيجيات:

استراتيجية التخزين المؤقت آلية العمل الهندسية أفضل استخدام عملي (Use Case)
1. الكاش أولاً (Cache-First) يقرأ الملف من الكاش المحلي فوراً؛ ولا يتصل بالشبكة إلا إذا لم يكن الملف موجوداً في الكاش. ملفات الخطوط (.woff2)، الأيقونات الثابتة، وملفات CSS/JS المزودة برقم إصدار (?v=1.1.54).
2. الشبكة أولاً مع بديل الكاش (Network-First) يجلب أحدث نسخة من السيرفر ويحدث الكاش؛ وإذا كان الإنترنت مقطوعاً يعرض النسخة المحفوظة أو صفحة offline.html. صفحات HTML للمقالات، الفهارس المتجددة، وأسعار الصرف والبيانات الحية.
3. العرض الفوري مع التحديث الخلفي (Stale-While-Revalidate) يعرض النسخة المخزنة في الكاش فوراً للزائر لسرعة قصوى، وفي نفس اللحظة يطلب نسخة محدثة من الشبكة في الخلفية للزيارة القادمة. صور المقالات (WebP)، الصور الرمزية للكتّاب، والبيانات شبه الثابتة.

4. التطبيق العملي: كود بناء ملف sw.js احترافي مع صفحة Offline Fallback

إليك الهيكل الهندسي المعتمد لبناء ملف sw.js يجمع بين الاستراتيجيات الثلاث ويوفر صفحة بديلة أنيقة عند انقطاع الإنترنت:

كود Service Worker (sw.js) هجين يدعم التحديث الذكي والعمل بدون إنترنت 
const CACHE_VERSION = 'v108';
const STATIC_CACHE = 'ct-static-' + CACHE_VERSION;
const OFFLINE_URL = '/offline.html';

const PRECACHE_ASSETS = [
  '/',
  OFFLINE_URL,
  '/assets/css/styles.min.css?v=1.1.54',
  '/assets/js/components/components-bundle.js?v=1.1.54',
  '/assets/fonts/cairo-arabic.woff2?v=1.1.60'
];

// 1. مرحلة التثبيت: حفظ ملفات الـ App Shell الأساسية
self.addEventListener('install', event => {
  event.waitUntil(
    caches.open(STATIC_CACHE)
      .then(cache => cache.addAll(PRECACHE_ASSETS))
      .then(() => self.skipWaiting())
  );
});

// 2. مرحلة التفعيل: حذف مخازن الكاش القديمة فوراً
self.addEventListener('activate', event => {
  event.waitUntil(
    caches.keys().then(keys => Promise.all(
      keys.filter(key => key !== STATIC_CACHE).map(key => caches.delete(key))
    )).then(() => self.clients.claim())
  );
});

// 3. اعتراض الطلبات: Network-First لصفحات HTML و Cache-First للأصول الثابتة
self.addEventListener('fetch', event => {
  if (event.request.mode === 'navigate') {
    event.respondWith(
      fetch(event.request).catch(() => caches.match(event.request) || caches.match(OFFLINE_URL))
    );
    return;
  }
  event.respondWith(
    caches.match(event.request).then(cached => cached || fetch(event.request))
  );
});

5. كيف تمنع بقاء الزائر على النسخة القديمة؟ هندسة إصدارات الكاش (Cache Busting)

من أشهر المشاكل الهندسية بعد إطلاق Service Worker هي أن المطور يعدّل ملف styles.min.css أو components-bundle.js ويرفعه للسيرفر، لكن الزوار القدامى لا يرون التعديل لأن المتصفح يقرأ النسخة القديمة من الكاش!

في منظومة كونكت تاق، حللنا هذه المشكلة جذرياً عبر أتمتة مزامنة الإصدارات المركزية (Automated Version Sync):

  • نحتفظ بملف مركزي واحد للإصدار (version.json) يحتوي على رقم الإصدار الدلالي (1.1.54) ورقم إصدار الكاش (v108).
  • عند تنفيذ سكربت النشر، يقوم السكربت تلقائياً بتحديث ثابت CACHE_VERSION داخل ملف sw.js، وتحديث معامل الاستعلام ?v=1.1.54 في جميع روابط ملفات CSS وJS والخطوط عبر كافة صفحات الموقع.
  • بمجرد أن يزور المستخدم الموقع، يكتشف المتصفح تغيّر بايت واحد على الأقل في ملف sw.js، فيقوم بتثبيت العامل الجديد ومسح الكاش القديم (v107) وتحميل الأصول المحدثة فوراً دون أي تدخل يدوي من الزائر!

6. فحص جاهزية الـ PWA وتشغيل الويب محلياً عبر مكتبة local-web-server

قبل إطلاق تطبيق الويب التقدمي الخاص بك، ننصحك بإجراء خطوتين عمليتين:

  1. فحص الوسوم التقنية وأمان الرؤوس (Technical SEO & Security Audit): استخدم أداة فحص الموقع والـ SEO في كونكت تاق (وراجع دليل الفحص التقني الشامل للمواقع) للتأكد من وجود وسوم manifest.json، وapple-touch-icon، وtheme-color، وتفعيل ترويسة الأمان Strict-Transport-Security (HSTS) الضرورية لعمل الـ Service Worker.
  2. تضمين تطبيقات الويب داخل تطبيقات أندرويد بدون إنترنت: إذا كنت تطور تطبيق أندرويد هجيناً يحتاج إلى تقديم ملفات ويب تفاعلية أو خرائط أو وثائق محلية عبر WebView دون الاعتماد على خادم خارجي، فقد طورنا في كونكت تاق مكتبة local-web-server ومكتبة webview-lib-kmp المتاحتين ضمن قسم المكاتب البرمجية المفتوحة المصدر لتشغيل خادم HTTP محلي خفيف الوزن داخل الهاتف نفسه! وللمشاريع المؤسسية المتكاملة، يمكنك طلب استشارة فريقنا عبر خدمة تطوير المواقع والأنظمة السحابية.

7. الأسئلة الشائعة حول تطبيقات الويب التقدمية (PWA)

لماذا يشترط المتصفح وجود شهادة أمان HTTPS لتفعيل Service Worker في تطبيقات PWA؟

لأن Service Worker يعمل كوكيل شبكي (Network Proxy) داخل متصفح المستخدم يمتلك صلاحية اعتراض جميع طلبات HTTP وتعديل استجاباتها وتخزينها محلياً. لو سُمح بتشغيله عبر اتصال HTTP غير مشفر، لتمكّن أي مهاجم على الشبكة (Man-in-the-Middle) من حقن ملف Service Worker خبيث يظل مسيطراً على المتصفح حتى بعد مغادرة الشبكة؛ لذا يُحصر تشغيله في نطاقات HTTPS الآمنة (مع استثناء localhost لأغراض التطوير).

ما الفرق بين استراتيجية Cache-First واستراتيجية Network-First في Service Worker؟

في استراتيجية Cache-First، يبحث الـ Service Worker عن الملف في الذاكرة المؤقتة المحلية أولاً وإذا وجده يعرضه فوراً بدون الاتصال بالشبكة، وهي مثالية للأصول الثابتة مثل الخطوط (woff2) والأيقونات والملفات المرقمة بإصدار. أما في استراتيجية Network-First، فيحاول جلب أحدث نسخة من الخادم أولاً، ولا يلجأ للكاش المحلي إلا عند انقطاع الإنترنت أو بطء الشبكة، وهي مثالية لصفحات HTML المتجددة والمقالات.

كيف أحل مشكلة بقاء الزوار على النسخة القديمة من الموقع بعد رفع تحديث جديد بسبب كاش الـ Service Worker؟

يتم حلها عبر الجمع بين آليتين: أولاً، ربط اسم مخزن الكاش في ملف sw.js برقم إصدار متسلسل (مثل CACHE_NAME = 'ct-cache-v108') وحذف جميع مخازن الكاش القديمة داخل حدث activate عبر caches.delete(). ثانياً، استدعاء self.skipWaiting() وclients.claim() مع إرفاق معامل إصدار (?v=1.1.54) بروابط ملفات CSS وJS لضمان تحديث الأصول فور نشر الإصدار الجديد.

هل تدعم أجهزة iPhone وiPad (متصفح Safari على iOS) تثبيت تطبيقات الويب التقدمية PWA؟

نعم، يدعم نظام iOS وiPadOS تشغيل تطبيقات الويب التقدمية عبر خيار «إضافة إلى الشاشة الرئيسية» (Add to Home Screen) في متصفح Safari، شريطة توفير ملف manifest.json سليم ووسوم أبل المخصصة مثل apple-touch-icon وapple-mobile-web-app-capable، كما أضافت أبل دعم الإشعارات الفورية (Web Push Notifications) لتطبيقات PWA المثبتة على الشاشة الرئيسية.
